# HermesShield Containment and Security Boundary

## Overview
This document describes the security boundary around the Hermes Agent when running inside NemoClaw/OpenShell sandbox environments. It documents the trust boundary between the host system and the sandboxed agent execution environment, along with runtime verification results.

## NemoClaw/OpenShell Sandbox Architecture

```
+--------------------------------------------------------+
|                    HOST SYSTEM                         |
|                                                        |
|  +----------------------+    +----------------------+  |
|  |  OpenShell Session   |    |   NemoClaw Layer     |  |
|  |  (agent session)     |    | (syscall filtering)  |  |
|  +----------+-----------+    +---------+-----------+  |
|                |                         |             |
|                |                         |             |
|      +---------v----------+  +-----v-----+   |
|      | Hermes Agent       |  | Tool exec|   |
|      | (sandboxed)        |  | (process|   |
|      +--------------------+  |  sandboxes|   |
|                           |   )      |   |
|                           +-----+------+   |
|                                   |       |
|                     +-------------v-----------+ |
|                     | Isolated Filesystem   | |
|                     |  - Read-only host     | |
|                     |  - /tmp writable only | |
|                     |  - Per-audit sandbox  | |
|                     +-----------------------+ |
|                       +-------+-------+       |
|                       |   Network Stack   |      |
|                       |   - Egress filtered |    |
|                       |   - DNS allowlist   |    |
|                       |   - No inbound      |    |
|                       +-----------------------+ |
+--------------------------------------------------------+
```

## Trust Boundary Definition

The trust boundary between **Host** and **Sandbox** is defined as:

| Direction | Boundary | Data Flow | Trust Level |
|-----------|----------|-----------|-------------|
| Host -> Sandbox | Sandbox initialization | Environment variables, working directory, allowed command set | Conditional (policy-enforced) |
| Sandbox -> Host | Process exit / file write | Evidence files, audit reports, tool output | Conditional (redacted, restricted) |
| Sandbox -> Network | Tool command egress | DNS queries, target endpoint connectivity | Distrusted (filtered) |
| Network -> Sandbox | Tool command results | Scanner output, web page data | Distrusted (validated) |

## Security Policy (Least Privilege)

### Explicitly Allowed Operations
1. **Filesystem**: Read-only access to Hermes source directory and audit data
2. **Filesystem**: Write access to `/tmp` directory within sandbox (for tool outputs)
3. **Filesystem**: Evidence file persistence to `audit_data/evidence/` (restricted permissions, chmod 600)
4. **Network**: DNS resolution for target endpoint discovery
5. **Network**: Outbound TCP connections to explicitly approved IP ranges/hosts
6. **Process**: Execution of allowlisted CLI tools (nmap, nikto, whatweb, dirb, gau, waybackurls, ffuf)
7. **Environment**: Only `ALLOWED_ENV` variables passed to subprocesses
8. **Credential**: No automatic credential access; credentials injected via environment only

### Explicitly Denied Operations
1. **Filesystem**: Write access to host home directory, system directories, or paths outside sandbox scope
2. **Filesystem**: Recursive directory traversal beyond `/tmp` and audit root
3. **Network**: Outbound connections to any host not in the DNS allowlist
4. **Network**: Inbound network connections of any kind
5. **Process**: Execution of commands not in the allowlisted tool set
6. **Process**: Spawning child processes from within tool execution sandboxes
7. **Credential**: Reading or exporting API keys, secrets, or PII from environment
8. **System**: Access to hardware interfaces, GPU, or device files
9. **System**: Modification of system state, registry, or persistent configuration

## Configuration Files

All security policies are documented in `policies/`:

| File | Purpose |
|------|---------|
| `policies/nemo_claw_policy.json` | Syscall filtering and process isolation config |
| `policies/open_shell_policy.json` | Restricted shell access config |
| `policies/tool_allowlist.json` | Command allowlisting with permitted arguments |
| `policies/evidence_redaction.json` | Regex patterns for sensitive data masking |
| `policies/network_policy.json` | Network egress filtering configuration |

## Filesystem Restrictions (Enforced)

| Restriction | Mechanism | Status |
|-------------|-----------|--------|
| Read-only host filesystem | Bind mount with `ro` flag via NemoClaw | VERIFIED (TEST 1, TEST 2) |
| Limited write access | Bind mount of `/tmp` only | VERIFIED |
| Evidence directory | Specific path mount with `chmod 600` | VERIFIED |
| No home directory access | Unmount `~` | Enforced |
| No system library access | Unmount `/lib`, `/usr` | Enforced |

## Network Restrictions (Enforced)

| Restriction | Mechanism | Status |
|-------------|-----------|--------|
| Egress filter | Default-deny with allow-list | VERIFIED (TEST 4) |
| DNS allowlist | Only specified DNS servers | VERIFIED |
| Target endpoint only | Connections only to audit target | Configured |
| No inbound connections | All inbound ports DROP | Enforced |

## Credential Handling

| Control | Mechanism | Status |
|---------|-----------|--------|
| No hardcoded credentials | API keys injected at process start | Configured |
| Environment variable filter | Only `ALLOWED_ENV` variables passed | Configured |
| Credential redaction | Regex-based before persistence | Configured (needs pattern refinement) |
| No credential export | Process environment blocked | Configured |
